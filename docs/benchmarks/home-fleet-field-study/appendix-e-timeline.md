# Appendix E. Fleet-state timeline (2026-08-27 to 2026-11-21)

Changes to firmware, access points, sink software and capture that plausibly moved the data a test consumed. AP-A is the access point the whole fleet associates to; AP-B is a second access point of the same model class used only for a short test. All dates are 2026.

| date | layer | change | effect on data |
|---|---|---|---|
| 08-27..08-29 | firmware | 3-node C6 fleet only. ESP-NOW beacon period 80 ms, in-flight guard, stall recovery flashed to all 3. ESP-NOW time sync confirmed live and the fps-estimator bias fixed (08-29). | Fleet = 3 nodes; 65-min empty-room baseline (8/9 links present). fps estimator had read 21% high before the fix. |
| 08-29..09-01 | node | Fleet grows 3 -> 9 (two 3-packs arrive 08-29). Sink link-table limit raised (MAX_LINKS 64 -> 256, LINK_HISTORY 64 -> 32) which invalidated the 3-node baseline. | Links per receiver 2 -> 8 peers + AP; per-link rate ~6 fps at 9 nodes. All pre-08-29 recordings are a different instrument. |
| 08-31..09-01 | node | Last physical moves: node 5 to the SE corner (was worst in fleet), node 8 from a cabinet to a counter-height outlet (+11 dB), guest-room node move planned. Positions confirmed accurate 09-01.
