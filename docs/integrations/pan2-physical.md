# PAN2 physical forecast integration

Status: optional experimental engine API, disabled by default. SYNTHETIC fixture
validation is distinct from live PAN2 inference and RF hardware validation.

## Boundaries

The `wifi-densepose-engine` feature `pan2-physical` consumes the optimized
WorldGraph physical adapter through the existing submodule. It does not copy the
model implementation, run inference during `process_cycle`, expose a network
endpoint, or write predictions into live tracks, fusion decisions, witnesses or
Homecore automation.

The submodule is pinned to `1c0eaf3f567f40b4430e99bdca78e84fe90b8e45`, the
implementation in [WorldGraph PR 18](https://github.com/ruvnet/worldgraph/pull/18).
That upstream PR is still draft. This RuView PR must remain draft until the
upstream dependency and its broader graph changes are reviewed. The pin advances
from `4441bc07b566659877c25e22cd5aea457bdba4f2`; it includes intermediate
WorldGraph changes, not only the PAN2 module. No branch tip is resolved at runtime.

## Flow

1. Explicitly enable the Cargo feature and runtime `PhysicalForecastConfig`.
   Fixture responses need a separate `allow_fixtures` opt-in.
2. Call `prepare_physical_forecast` with selected engine-owned tracker IDs,
   calibrated ENU geometry, a bounded action, source time and prediction horizon.
   Per-track forecasting is admitted only in `RawResearch` or `CareWithConsent`.
   PrivateHome, EnterpriseAnonymous and StrictNoIdentity reject. A caller-provided
   privacy label cannot override this gate. Hosted processing approval is removed.
3. The ticket captures an immutable source graph and the current privacy
   attestation. Its scene excludes raw CSI and re-ID embeddings before sending
   a request to the local `Pan2PhysicalBridge`. Run that work on a separate task;
   do not hold the live engine lock while waiting for the worker.
4. Call `finish_physical_forecast` with the worker branch and a trusted current
   clock. It rechecks enablement, privacy attestation, fixture admission, request
   hash and horizon. Policy changes, including changing away and back, reject.
   Replay uses the same admission checks via `replay_physical_forecast`.
5. The returned hypothesis graph is based on the captured source, not the latest
   measured graph. New sensing updates can continue during generation. The
   result exposes its source cycle, and the upstream request retains the source
   epoch, time, frame and calibration. Call `result.branch().reconcile(...)` with
   later independent measurements to compare forecast errors.

The caller must supply a trusted observation/current clock and authorize action
text and geometry before preparation. Keep retained tickets/results under the
deployment's local retention policy. The engine does not persist them. A request
already sent cannot be recalled when privacy changes; completion is rejected and
the local worker must separately implement cancellation and retention.

## Build and acceptance

```sh
git submodule update --init --depth 1 \
  v2/crates/worldgraph v2/crates/ruview-swarm v2/crates/ruforecast vendor/rufield
cd v2
cargo test -p wifi-densepose-engine --no-default-features --features pan2-physical --locked
cargo test -p wifi-densepose-engine --no-default-features --locked
```

The fixture tests require no model weights or GPU. They exercise engine track
projection, immutable asynchronous completion, privacy modes and attestation
changes, default-off and fixture gating, request mismatch, expiry and collision
rejection. Successful results must leave the live graph byte-identical, including
updates made after ticket preparation. Tests are SYNTHETIC, not forecasting
accuracy or real RF/hardware evidence.

## Live prerequisites

PAN2 still generates perceptual video/latent predictions. A separately deployed
CUDA worker, complete checkpoints and a calibrated metric extractor must convert
its outputs to the structured trajectory protocol. None is downloaded or started
by this integration. No metric extractor is implemented here.

PAN2 generation latency must be shorter than the admitted forecast horizon for
live use; otherwise completion rejects as expired. Benchmark real observations
against stationary and constant-velocity baselines before production enablement.
Model/artifact hashes and `execution: pan2` are worker assertions, not execution
attestations. This is not a rigid-body solver or a safety-critical controller.

Rollback: disable the runtime setting or compile without `pan2-physical`.
Existing observed snapshots require no migration.

## Validation evidence

MEASURED on ruOS with the repository-pinned Rust 1.89 toolchain: both focused
engine commands above completed with exit code zero, with and without the
optional feature. Fixtures are SYNTHETIC. The committed dependency lock matches
the lock generated by Cargo for this integration. Missing executor OpenSSL
development prerequisites were supplied locally; no system paths or credentials
are committed. Broader RuView workspace/hardware and live PAN2/extractor
validation remain outside this focused engine result.
