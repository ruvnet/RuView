# RuView ESP32 firmware 0.8.17 prerelease

Firmware 0.8.17 adds an experimental ESP32-C5 headless bundle alongside the
existing S3 and C6 targets, with guarded C5 installation and matching
user/build guides.

## Changes

- An experimental ESP32-C5 headless bundle ships beside the S3 and C6 ones.
  The C5 bootloader is at `0x2000`; select the matching bundle and verify both
  the archive and the image checksums.
- Legacy mmWave GPIO17/18 probing no longer reroutes the C5 flash/PSRAM bus.
  Unconfigured C5 sensor probes are skipped, and explicit pins are checked
  against memory and console assignments.
- Flash qualification and the public SDK monitor reject watchdog/flash-busy
  evidence even when initial CSI callbacks appear.
- C5 writes require production-chip identity, sufficient flash and
  `esptool >= 5.3`.
- `libz-sys` is updated for RUSTSEC-2026-0418, and the harness test concurrency
  is bounded for the Windows helper startup.

## Validation

- **MEASURED** (bounded real hardware; reproducer in the linked record): a
  production ESP32-C5HR8 revision 1.2 with 8 MB flash was backed up, installed
  and provisioned. The corrected 0.8.17 firmware booted and streamed real CSI
  without captured watchdog/flash-busy errors in bounded captures. The
  production SDK receiver decoded all 971 packets in its recorded sample with
  no malformed or unknown packets.
- The firmware release workflow run
  <https://github.com/ruvnet/RuView/actions/runs/40915261010> completed
  successfully after an empty duplicate staging draft was removed. All four
  final archives passed the outer and inner checksums and the embedded
  version/chip checks; the C5 bundle matched the exact CI artifact and the
  images installed on COM8. An anonymous download returned HTTP 200 with a
  matching checksum.
- The final release-image check decoded all 479 received packets, including 371
  raw CSI frames, with no unknown or malformed packets, and the public serial
  monitor passed. A separate five-minute corrected-firmware run decoded all
  5,318 packets, including 4,197 raw CSI frames, without captured firmware
  faults or disconnects.

## Limits

- Cadence is AP-dependent: the recorded raw CSI samples were roughly 12-29
  packets/s, and bounded extra traffic did not produce a consistent
  improvement. That setup did not consistently meet the 20 packets/s
  acceptance target.
- C5 remains experimental. This is not a sensing-accuracy, comparative speedup
  or long-run reliability qualification.
- The measured profile was 2.4 GHz, 240 MHz CPU, 8 Hz edge DSP, 4 MB OTA
  layout and UART console, with display, WASM and PSRAM disabled. 5 GHz is not
  qualified, and the exact board form factor remains operator-unconfirmed: the
  generic profile has no LED or default sensor pin assignment.
- The published server image `ghcr.io/ruvnet/wifi-densepose:v0.8.17-esp32` was
  checked against the attached C5 in an ephemeral container (`/health` 200,
  unauthenticated API 401, authenticated API 200, C5 node active with an
  advancing CSI sequence over six seconds). That is software/transport
  compatibility evidence, not a matched hardware-performance comparison or a
  sensing-accuracy qualification.
- `@ruvnet/ruview@0.9.3` remains unpublished pending registry authorization
  ([#2390](https://github.com/ruvnet/RuView/issues/2390)). No workstation npm
  publish was attempted; use the checked-out `main` source installer for C5
  support meanwhile.
